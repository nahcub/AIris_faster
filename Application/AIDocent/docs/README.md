# docs/ — 무엇을 어디에 쓰나

문서가 흩어져 같은 얘기를 다르게 하는 걸 막으려고 **역할로** 나눴다. 폴더가 곧 규칙이다.

| 폴더 | 무엇 | 고쳐도 되나 | 파일명 |
|---|---|---|---|
| `plan/` | **살아있는 계획.** 지금 뭘 하려는지 | ✅ **고쳐 쓴다.** 낡은 문장은 지운다 | 날짜 없음 (`rag-roadmap.md`) |
| `notes/` | **시점 기록.** 그날 잰 것, 그날 알아낸 것 | ❌ 원칙적으로 덧붙이기만 | 날짜 붙임 (`2026-08-15-phase2-retrieval.md`) |
| `archive/` | **과거 축.** 지금은 안 쓰는 문서 | — | 원래 이름 |

그리고 `../CLAUDE.md`가 **"지금 상태 + 코드 지도 + 작업 규칙"의 단일 출처**다.
세 폴더가 서로 어긋나면 CLAUDE.md를 믿는다.

## 왜 이렇게 나눴나

계획과 기록은 **수명이 반대**다. 계획은 틀리면 고쳐야 하고, 기록은 나중에 틀린 걸 알아도
그대로 둬야 한다 — "그때 이렇게 알고 있었다"가 그 문서의 값어치이기 때문이다.
둘을 한 폴더에 두면 날짜 붙은 파일을 계속 고치게 되고(파일명이 거짓말이 된다),
반대로 계획을 못 고치고 새 파일을 만들게 된다(같은 주제가 여러 벌로 갈라진다).
실제로 `2026-08-13-rag-roadmap.md`가 08-15에 수정되고 있었고, 그게 이 분리의 계기다.

## 새 문서를 쓸 때

1. **계획을 바꾸는 것인가?** → `plan/`의 기존 파일을 **고친다.** 새 파일 만들지 말 것
2. **측정하거나 알아낸 것인가?** → `notes/`에 `YYYY-MM-DD-주제.md`로 **새로** 쓴다
3. **어느 쪽인지 애매한가?** → 6개월 뒤에도 유효할 문장이면 `plan/`, "그날 그랬다"면 `notes/`
4. 어느 경우든 **`CLAUDE.md`의 상태표를 같이 갱신**한다. 새 문서만 쓰고 CLAUDE.md를 안 고치면
   다음 세션은 그 문서의 존재를 모른다
